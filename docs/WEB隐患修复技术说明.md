# Web 隐患修复技术说明

## 范围

本次修复针对 Web 安全审查中发现的数据生命周期、局域网暴露、文件恢复覆盖和请求资源耗尽问题。服务仍按单机工具运行，默认地址为 `127.0.0.1`；当前版本不提供用户账号体系。

## 1. 为避免停止视频任务误删历史记录文件，按照上传文件租约和数据库引用检查方式，避免共享文件被误删

- 图片继续按完整 SHA-256 内容摘要去重；命中已有摘要路径时再逐块比较内容，大小相同或摘要相同本身不作为内容一致的唯一依据。
- 视频源文件采用独立文件名，不参与上传去重，保证一个视频任务拥有独立源文件。
- `save_upload` 从创建临时文件开始登记租约，落位时在同一把锁内将租约转移到正式文件；图片检测、视频任务结束或失败后释放租约。
- 取消、失败、超时回收只有在没有其它活动租约、且数据库中没有记录引用该文件时才删除源文件。
- 孤儿回收、重复文件清理和临时文件清理在实际移动/删除时再次持有租约锁判断，避免清理扫描与新上传并发时误删文件。

因此，停止某个视频任务不会删除历史记录仍引用的文件；并发复用同一张图片时，也不会因其中一个请求失败而删除另一个请求正在处理的文件。

涉及文件：[file_utils.py](../app/utils/file_utils.py)、[video_task.py](../app/core/video_task.py)、[storage.py](../app/core/storage.py)、[cleaner.py](../app/core/cleaner.py)、[detect.py](../app/api/detect.py)

## 2. 为避免无鉴权管理接口被局域网调用，按照本机回环访问和同源校验方式，避免远程读取或修改本机数据

- `run.py` 拒绝绑定 `0.0.0.0`、局域网地址及公网地址，只允许回环地址。
- ASGI 入口再次校验客户端地址和 `Host`，只接受本机回环地址；拒绝非本机客户端及 DNS rebinding 域名，因此直接使用 Uvicorn 绑定网卡也不能绕过访问边界。
- 对 API 与 WebSocket 请求校验 `Origin` 主机，拒绝跨来源浏览器调用。
- 移除通配符 CORS 配置。前端由同一服务提供，正常同源请求不需要 CORS。
- 当前版本不支持远程访问或未经专门配置的反向代理；如需远程使用，应先实现身份认证、可信代理与允许的外部 Host/Origin 配置并单独审查，不得直接暴露应用端口。

涉及文件：[web_guard.py](../app/utils/web_guard.py)、[main.py](../app/main.py)、[run.py](../run.py)、[README.md](../README.md)

## 3. 为避免恢复回收站文件覆盖同名现存文件，按照排他创建和冲突返回方式，避免覆盖活动文件或历史记录内容

- 恢复时使用操作系统的排他创建标志创建目标文件，不覆盖已经存在的路径。
- 创建目标失败时保留回收站源文件；同名冲突由 API 返回 HTTP `409 RESTORE_CONFLICT`，提示先处理现存文件。
- 文件复制失败时删除本次创建的不完整目标，保留原回收站文件供再次恢复。

涉及文件：[storage.py](../app/core/storage.py)、[system.py](../app/api/system.py)

## 4. 为避免大请求或超大图像耗尽内存和临时磁盘，按照入口请求体限额及解码像素上限方式，避免资源耗尽

- 在 ASGI multipart 解析之前按原始请求体字节数限制上传：单图/单视频为单文件上限加 multipart 余量；批量图片上限与接口累计文件预算一致；其它 JSON 请求体限制为 2 MiB。
- 同时检查 `Content-Length` 和实际接收字节数，因此没有 `Content-Length` 的分块请求也受限制。
- 图片先读取图像头尺寸，再交给 OpenCV 解码；图片及视频帧均限制为最多 25,000,000 像素，超出时返回可读的文件错误。

涉及文件：[web_guard.py](../app/utils/web_guard.py)、[image_utils.py](../app/utils/image_utils.py)、[video_task.py](../app/core/video_task.py)

## 5. 为避免无效图片上传在检测失败后持续占用磁盘，按照租约释放和引用计数方式，避免遗留文件误删有效数据或无限累积

- 单张和批量图片检测均在成功、失败两条路径释放上传租约。
- 检测失败时，仅当没有活动租约且数据库没有任何引用时才删除上传文件。
- 若无法确认数据库引用状态，则保留文件并交由孤儿文件治理流程处理，采用保留优先的失败策略。

涉及文件：[detect.py](../app/api/detect.py)、[file_utils.py](../app/utils/file_utils.py)

## 6. 为避免视频暂停后任务长期滞留并占住跟踪器，按照可恢复暂停、显式停止和线程池安全回收方式，避免后续视频任务持续报错

- 暂停期间停止读取和推理视频帧，同时每 3 秒发送一次轻量 `paused` 心跳；连接断开能进入 WebSocket 收尾流程，不会因为暂停状态而永远没有 I/O。
- 控制接口提供 `pause`、`resume`、`stop` 和阈值调整；停止时先设置取消标志，运行中的任务由 WebSocket `finally` 统一移除，尚未开始的任务则由控制接口立即回收。
- 跟踪器独占槽位放在任务 `finally` 中释放，因此正常结束、暂停后停止、WebSocket 断开或异常均会释放。
- 关闭线程池时先阻止新任务提交，再等待正在执行的解码/推理线程结束；API 在线程池中执行阻塞关闭，避免卡住事件循环或与 OpenCV writer 并发释放。
- 视频源文件按任务独立保存，停止任务不会误删其它任务或历史记录引用的共享文件。

涉及文件：[video.js](../web/js/video.js)、[detect.py](../app/api/detect.py)、[video_task.py](../app/core/video_task.py)

## 验证清单

- Python 后端模块编译检查。
- 前端 `video.js`、`system.js` 语法检查。
- 本机健康检查及系统状态查询。
- 视频暂停/继续/停止后再次启动第二个视频任务，确认 `video_tasks=0` 且 `tracking_busy=false`。
- 上传失败后的文件租约释放与数据库引用保护。
- 临时上传期间并发触发清理时保留临时文件；发布文件与清理操作按租约锁串行。
- 拒绝非回环客户端、非本机 Host、DNS rebinding Host 和跨来源 API/WebSocket 请求。
- 单文件、批量文件与普通请求体的大小限制。
- 超过像素上限的图片/视频在推理前拒绝。
- 回收站同名目标冲突时返回 409，源文件仍留在回收站。
