# 基于深度学习的水下海洋生物目标检测与分析系统

基于 GSCNet 的水下海洋生物检测 Web 系统。上传图片或视频 → 模型推理 → 显示检测框与置信度 →
统计检出框与跟踪轨迹 → 保存记录 → 生成统计图表。后端 FastAPI + SQLite，前端原生 HTML/CSS/JS + Chart.js，
视频检测通过 WebSocket 实时推流。

2026-10-19 修复说明见 [实际应用问题修复记录](docs/实际应用问题修复记录-2026-10-19.md)。本轮按要求保留 YOLO 类别编号逻辑，其余已定位软件缺陷已修复；图片类别分布采用每份素材最新成功检测，视频跟踪不完整时不提供唯一数量。

## 二、安装步骤

### 1. 创建并激活虚拟环境

```bat
python -m venv .venv
.venv\Scripts\activate
```

> 启动脚本会从项目目录定位代码与资源。克隆仓库后请按本节创建虚拟环境并安装依赖；移动项目后，若虚拟环境无法启动，请在项目根目录重新创建 `.venv`。

### 2. 安装 PyTorch（CPU 版，无 NVIDIA 显卡时必须用这个源，否则会装 2GB+ 的 CUDA 包）

```bat
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

> 若下载慢，可先执行 `pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/`，
> 但 **torch 仍建议使用上面的官方 CPU 源**。

### 3. 安装其余依赖

```bat
pip install -r requirements.txt
```

### 4. 放入模型权重

本仓库不附带任何 `.pt` 权重文件。首次使用前，请将自己训练的权重上传到项目根目录下的 `models/`，例如 `models/best.pt`。程序默认扫描 `models/` 并选择找到的第一个 `.pt` 文件；也可在项目根目录的 `config.yaml` 中将 `model_path` 设为相对于项目根目录的路径。具体步骤见 [`models/README.md`](models/README.md)。

## 三、启动系统

### 方式一：双击 `start.bat`（最简单）

优先使用项目目录内的 `.venv` 环境并检查依赖，然后启动服务并打开 **http://127.0.0.1:8000**

### 方式二：命令行

```bat

:: 本机已配置好的虚拟环境（推荐，依赖已装齐）
.venv\Scripts\python.exe run.py

:: 或使用自己创建的环境
python run.py
```

默认地址：**http://127.0.0.1:8000**

可选参数：

```bat
python run.py --port 8080        :: 指定端口（端口被占用时会自动向后寻找可用端口）
python run.py --host 0.0.0.0     :: 当前版本会拒绝非本机监听（管理 API 暂无账号鉴权）
python run.py --reload           :: 开发模式，代码修改后自动重启
```

启动成功后浏览器会自动打开首页即可使用；若未自动打开，手动访问上面的地址。

服务强制限制为本机访问，管理 API 当前没有账号体系。当前版本不支持远程访问或未经专门配置的
反向代理；不要直接把服务端口暴露到局域网或公网。各项安全修复与验证记录见
[Web 隐患修复技术说明](docs/WEB隐患修复技术说明.md)。

### 图片队列与后台视频（2026-10-24）

- 图片按队列逐张处理，可查看等待、上传、推理、成功、失败和取消状态。
- 可取消单张或全部尚未开始的图片；当前图片继续完成并保存。
- 点击“仅重试失败项”沿用本批次置信度和调查信息，成功图片不再提交；
  同一服务运行期间的短期重试会复用已保存结果，避免响应丢失后立即重试导致重复记录。
- 视频上传成功后由后台继续处理。切换页面、刷新或关闭预览不停止任务，
  返回视频页可自动恢复上次查看的任务，也可在“后台视频任务”中选择。
- 多个页面共享同一个视频任务，暂停、继续、阈值修改和停止会同步；预览断开时自动重连。
- 停止未完成视频不保存成功记录，资源释放后可以启动下一次检测。
- 后台继续以服务保持运行为前提；服务退出或电脑关机后，未完成视频需重新上传。
  最近完成入口最多保留 20 项、最长一小时，完成的数据库记录与视频文件按既有保留策略保存。

### 典型使用流程

**图片检测（支持批量）**：打开「图片检测」→ 点击或拖拽选择**一张或多张**图片（单次最多 20 张）→
可调置信度阈值 → 点「开始检测」→ 结果以网格卡片展示，每张图都叠加检测框 → 顶部显示汇总
（图片数 / 目标总数 / 成功失败数 / 总耗时）→ 点击任意卡片查看大图与逐目标明细。

**视频检测**：打开「视频检测」→ 上传视频 → **拖动滑动条设定置信度阈值**（0.05~0.95，
值越低保留的候选框越多）→ 点「开始检测」→ 画面实时逐帧刷新并叠加检测框，下方实时更新
「当前帧目标数量 / **累计唯一目标** / 各类别数量 / FPS / 播放时间 / 单帧峰值」。
检测结束后可点击「**下载结果视频**」保存一份带检测框的 MP4（时长与原视频一致）。

检测过程中可以随时：
- 点「**暂停检测**」→ 画面叠加“已暂停”遮罩，服务端停止读帧与推送，**保留当前播放位置**；
- 点「**继续检测**」→ 从暂停位置接着处理，帧号连续，统计继续累计；
- **拖动滑动条** → 阈值立即对后续帧生效（例如从 0.5 调到 0.15 可发现更多小目标）；
- **点击类别标签** → 隐藏 / 显示该类别在画面上的检测框（只影响显示，不影响已保存的数据）；
- 点「停止检测」→ 中断本次任务（不保存记录）并释放跟踪器；暂停任务可从视频页或「系统状态」任务中心停止。

检测结束后展示全程汇总（**唯一目标数 / 累计检测框数** / 处理帧数 / 平均速度 / 单帧峰值 /
平均每帧目标数 / 各类别唯一目标数），记录自动入库。

**查看历史**：打开「检测记录」→ 列表直接显示**结果缩略图**（点击可放大）→ 按类型 / 文件名 /
日期筛选 → 点「详情」查看结果图 / **在线播放结果视频**、**类别分布与逐帧目标数图表**、
逐帧采样数据与目标明细 → 也可删除单条记录。

**浏览目标图库**：打开「目标图库」→ 按类别、素材类型、最低置信度或文件名筛选 → 点击目标卡片或「查看来源记录」打开对应记录详情。图片目标从原始上传图片按检测框裁剪；视频目标从已保存明细的采样帧裁剪，使用检测时记录的缩放参数还原坐标。视频采样不等于所有帧，同一生物可能出现多次，图库条数不能当作生物个体数。原文件缺失、帧无法读取或旧视频未记录缩放参数时，卡片会提示缩略图不可用；图库不修改原素材和检测结果。

记录页的批量能力（勾选栏内）：

- **对比所选**：勾选 2–4 条 → 并排查看计数口径、目标数、轨迹数、MaxN、置信度分布与阈值敏感性；
  口径不一致时副标题直接标明，不会被误读为可横向比较；底部「**导出对比 CSV**」把整张表（含口径判定）
  存为文件，带 BOM 便于 Excel 直接打开。
- **批量报告**：勾选图片记录 → 合成一份多页 PDF（单次上限 50 张），每页标注「影像 n/N」并附批次汇总。
- **导出标签**：勾选图片记录 → 按 CSV / COCO / YOLO 导出训练标签。
- 视频记录会自动排除（明细跨帧含轨迹，转成单图标签会失真），按钮计数按**实际参与导出的图片张数**显示，
  选择栏会说明「其中 N 条视频不参与报告 / 标签导出」。
- **翻页不会清空勾选**（勾选按记录 ID 维护），只有改动筛选条件才清空。
- 快捷键：`Ctrl/Cmd + A` **按剩余额度选中本页前几条**（受 4 条对比上限约束，本页 10 条时会提示
  「已选中前 4 条」），`Esc` 清空勾选（输入框内、弹窗打开时不抢占，避免误清或误全选）。

**导出前预检**：记录详情里的「导出预检」区块在**点之前**就给出结论——素材是否齐全、体积上界、
明细行数与累计检出的差距、计数口径是否回退、该记录能不能出标签。它是只读检查
（`GET /api/report/preflight/{id}`），不生成文件、不落盘，可随时调用。

**查看统计**：打开「数据统计」→ 查看今日/累计检测次数、目标总数、类别数 → 趋势粒度可切换
**7 / 14 / 30 天或 8 / 12 周** → 柱状图（每期检测次数）、折线图（每期检出目标数）、
**各类别随时间变化的多折线图**、**24 小时检测时段分布（橙色为最活跃时段）**、
饼图（类别占比）、环形图（图片 / 视频占比）。

**系统运维**：打开「系统状态」→ 顶部四张卡片给出服务状态、受管存储占用、可回收空间与驻留任务数 →
「磁盘与存储水位」用条形图展示主机磁盘占用与**上传 / 结果 / 回收站三者的构成占比** →
「运行指标」列出进程内存与 CPU、主机内存、数据库体积、模型与跟踪器、累计数据规模 →
「任务中心」列出所有驻留视频任务的状态与进度，可一键**回收僵尸任务** →
「运维操作」提供六个操作卡片（见下方第九章），危险操作均有二次确认 →
「回收站」列出被删除文件，可**逐个恢复**到原目录 → 页面底部展示治理审计日志与当前策略。
面板默认每 **10 秒自动刷新**（页面不可见时自动暂停，切换回来立即刷新），点击提示文字可暂停自动刷新。

## 五、模型与配置

所有参数集中在 `config.py` 与可选的根目录 `config.yaml`，代码中没有硬编码的路径或阈值。

配置优先级：**环境变量 > config.yaml > 默认值**。

常用配置项（复制 `config.example.yaml` 为 `config.yaml` 后修改即可）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `model_path` | `models/` 下第一个 `.pt` | 权重文件路径 |
| `conf_threshold` | 0.25 | 置信度阈值 |
| `iou_threshold` | 0.45 | NMS IoU 阈值 |
| `imgsz` | 640 | 模型输入尺寸 |
| `device` | auto | auto / cpu / cuda / 0 |
| `frame_skip` | 2 | 视频每 N 帧检测 1 帧（CPU 提速关键） |
| `video_max_side` | 960 | 视频帧长边缩放上限 |
| `jpeg_quality` | 70 | WebSocket 推流图像质量 |
| `push_fps_limit` | 20 | 推流帧率上限，0 表示不限 |
| `max_upload_mb` | 300 | 单文件上传大小上限 |
| `max_batch_images` | 20 | 批量图片检测单次最大张数 |
| `tracker` | `bytetrack.yaml` | 视频目标跟踪器配置（`bytetrack.yaml` / `botsort.yaml`） |
| `track_enabled` | `true` | 视频是否启用目标跟踪；关闭后回退为逐帧计数 |
| `save_result_video` | `true` | 视频检测是否同步导出带检测框的结果 MP4（关闭可省 CPU 与磁盘） |
| `class_name_map` | `{}` | 类别**显示名**映射（可选，见下方说明） |

### 资源治理配置

系统内置了四条防泄漏机制，避免长时间运行后磁盘 / 内存无限膨胀：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `max_active_video_tasks` | 3 | 同时驻留的视频任务上限，超出自动淘汰最久未开始的任务 |
| `video_task_ttl_sec` | 600 | 视频任务未连接 WebSocket 的存活秒数（下限 30s），超时自动回收并删除上传文件 |
| `auto_cleanup` | `true` | 服务启动时执行一次过期文件清理 |
| `file_retention_days` | 365 | 文件保留天数，`0` 表示完全不清理（默认一年，论文素材可长期留存） |
| `dedupe_upload` | `true` | 图片按文件内容 SHA-256 去重，重复上传直接复用磁盘已有文件 |

**为什么并发视频会被拒绝**：目标跟踪（ByteTrack）的轨迹状态是挂在共享模型实例上的
全局资源，两个视频同时检测时后者会重置前者的轨迹 ID，导致同一目标被重复计入
"唯一目标数"，且这种错误在页面上完全看不出来。因此系统在引擎层加了独占槽位，
同一时刻只允许一个视频任务运行，第二个会收到明确提示而非静默出错：

```json
{"success": false, "code": "TRACK_BUSY",
 "message": "已有视频检测任务正在运行。...请等待当前任务结束后再开始新的检测。"}
```

**为什么上传要去重**：同一个视频反复上传会产生多份 10MB+ 的完整副本。开启去重后
按内容 SHA-256 命名图片文件，重复内容只存一份并刷新其 mtime，既省磁盘又不会被保留策略误删；
视频任务使用独立文件，确保取消单个任务不会删除被其它记录引用的共享源文件。

### 类别名与中文显示（可选）

类别名始终从模型自身读取（`model.names`），当前权重返回的是 `hd / hx / hs / sb / other`，
代码中没有写死任何海洋生物类别。

如果想让页面显示中文名，复制 `config.example.yaml` 为 `config.yaml`，填上映射即可：

```yaml
class_name_map:
  hd: 海胆
  hx: 海星
  hs: 海参
  sb: 扇贝
  other: 其他
```

> 上面的中文对应关系是按 URPC 常见标注推测的，请以你自己数据集 `data.yaml` 的标注含义为准。
> 留空或不配置 = 直接显示模型原始类别名。

环境变量示例：`MODEL_PATH`、`CONF_THRESHOLD`、`IMGSZ`、`DEVICE`、`FRAME_SKIP`、`PORT`。

运行时调参：前端图片检测页可直接改置信度；也可调用 `PUT /api/config`（进程内生效）。

## 八、性能与优化

测试环境：Windows 11 / CPU 推理（无 NVIDIA 显卡）/ 权重 `models/best.pt`（YOLOv11，imgsz 640）。
真实实测数据见本文开头「项目当前状态」，均为实际运行采集，未使用任何估算或虚构数值。

CPU 较慢时的优化方式（只改配置，不用改代码）：

| 目标 | 调整方式 |
| --- | --- |
| 视频更快 | 增大 `frame_skip`（2 → 3~5，跳帧更多，统计仍实时刷新） |
| 单帧更快 | 减小 `imgsz`（640 → 480/416）、减小 `video_max_side`（960 → 640） |
| 推流更省带宽 | 降低 `jpeg_quality`（70 → 55） |
| 减少漏检 | 降低 `conf_threshold`（0.25 → 0.15，图片检测页可直接调） |

> 说明：视频默认启用目标跟踪（ByteTrack）。只有 `unique_count_valid=true` 时，`unique_objects` 才表示有效的跟踪轨迹数；否则为 `null`，应读取 `total_detections` 查看累计框数。
> 轨迹数不是经过人工确认的实际生物个体数。`counting_mode` 区分图片框数、完整跟踪、部分跟踪及逐帧统计。
> 页面同时给出「单帧峰值」与「平均每帧目标数」作为辅助参考。
## 九、资源治理与磁盘维护

系统针对长时间运行的资源泄漏做了四项防护，全部经过实测验证：

| 机制 | 解决的真实问题 | 触发方式 |
| --- | --- | --- |
| **视频跟踪独占槽位** | 并发视频导致 track_id 串号、唯一目标数静默算错 | 引擎层自动拦截，第二个任务返回 `TRACK_BUSY` |
| **僵尸任务回收** | 上传视频后不点「开始检测」就离开，任务与文件永久滞留 | TTL 超时 / 超出驻留上限时自动回收 |
| **WAL 自动 checkpoint** | `app.db-wal` 只增不减（实测曾膨胀到 3.4 MB，主库仅 4 KB） | 运行中自动 + 启动时 / 退出时各执行一次 |
| **文件去重 + 保留策略** | 重复上传图片产生多份完整副本 | 图片上传时按 SHA-256 复用；启动时按天数清理并同步删记录 |
| **引用计数 + 回收站** | 删除记录不释放磁盘 / 去重共享文件被误删 | 删文件前复核全库引用；文件先进回收站可恢复 |
| **存储治理可视化** | 治理能力齐全但只能敲 curl，运维门槛高 | `/system.html` 面板一键操作，见下 |

**运维面板（`/system.html`）提供的操作**

| 操作 | 作用 | 安全性 |
| --- | --- | --- |
| 孤儿文件回收 | 删除无任何记录引用的文件 | 支持预检；文件进回收站可恢复 |
| 重复副本清理 | 治理内容重复的存量文件 | 支持预检；被引用文件永不删除 |
| 临时残留清理 | 清 `.tmp_` 上传残留与 0 字节残骸 | 自动跳过被引用文件 |
| 过期记录清理 | 按保留期删记录 + 独占文件 | 支持预检；文件进回收站 |
| 数据库 WAL 合并 | 合并并截断 WAL，释放占用 | 只读合并，无数据风险 |
| 回收站清空 | 彻底删除滞留超窗口的文件 | 「全部清空」需二次确认且不可恢复 |
| 回收站恢复 | 把误删文件还原到原目录 | 逐个恢复，自动识别 uploads / results |

> 视频任务运行期间，所有会动文件的操作都会被拒绝（`SYSTEM_BUSY`），避免删掉任务正在读写的文件。

实测效果（同一份素材反复上传检测后）：

```
清理前:  uploads 20 个 / 44.3 MB     results 9 个 / 1.0 MB    合计 45.3 MB
清理后:  uploads  6 个 / 10.6 MB     results 9 个 / 1.0 MB    合计 11.6 MB  (节省 33.7 MB)
```

手动清理（可选，服务运行中也能调用）：

```bat
:: 先预检，只统计不删除
curl -X POST "http://127.0.0.1:8000/api/system/cleanup?dry_run=true"

:: 确认无误后实际执行（默认清理过期文件 + 重复副本）
curl -X POST "http://127.0.0.1:8000/api/system/cleanup"

:: 自定义保留期，例如只保留 3 天
curl -X POST "http://127.0.0.1:8000/api/system/cleanup?days=3"
```

> 说明：清理采用「**文件与记录同批删除**」策略，删除文件的同时删除其关联数据库记录，
> 不会出现记录详情页图片 404 的情况。有视频任务在队列中时会拒绝清理（`CLEANUP_BUSY`）。
>
> 关于查看视角：打开 `http://127.0.0.1:8000/api/health` 可直接看到当前磁盘占用、
> 驻留任务数与跟踪槽位状态。

## 十、检测报告（PDF）

图片检测完成后，结果区右上角提供 **「下载检测报告 (PDF)」** 按钮，一键把整批检测结果
导出为一份可直接用于汇报 / 论文附录的 PDF。

### 报告结构

报告以**一次上传的批次**为单位组织。例如一次拉入 5 张图片，就生成一份「5 张影像」的报告；
一次上传 2 张，则按 2 张生成，以此类推。

| 页码 | 内容 |
| --- | --- |
| 第 1 页 | 报告概览（批次影像数、目标总数、平均置信度、模型、阈值、设备）+ 批次总体结论 |
| 第 2 ~ N+1 页 | 逐图分析：**结果图（含检测框）+ 类别统计 + 结果分析 + 检测明细**，每张图各占一页 |
| 最后一页 | 全批次目标统计汇总 + 逐图产出对照（仅多图时报出） |

单图页采用**自适应排版**：图片高度按剩余空间动态压缩，明细表行数由实测可用高度反推，
确保「图 + 统计 + 结论 + 明细」稳定收进同一页，不出现跨页断裂。

### 按需生成（懒生成）

报告**仅在点击按钮时**才在后端合成，不会在检测完成时预生成，也不会缓存到磁盘：

- 后端用 `io.BytesIO` 在内存中生成 PDF，直接以流式响应回传，**服务端零落盘**；
- 前端拿到二进制流后用 `Blob` + 临时对象 URL 触发浏览器下载，下载后立即 `revokeObjectURL` 回收内存；
- 因此长时间不点击下载，也**不会占用任何额外内存或磁盘**。

### 调用方式

前端按钮会自动收集本次批次的 `record_id` 列表并提交；也可直接调用接口：

```bash
curl -X POST "http://127.0.0.1:8000/api/report/images" \
     -H "Content-Type: application/json" \
     -d '{"record_ids":[1,2,3]}' \
     -o 检测报告.pdf
```

请求体中的 `record_ids` 按数组顺序决定报告中影像的先后次序；接口返回
`Content-Type: application/pdf`，文件名同时给出 ASCII 与 RFC 5987 两种形式
（`filename*=UTF-8''...`），保证中文环境下载不乱码。异常分支返回统一 JSON 错误体
（`EMPTY_RECORDS` / `RECORDS_NOT_FOUND`）。

> 依赖：报告生成使用 `reportlab`（已列入 `requirements.txt`）。中文字体优先使用系统
> 微软雅黑 / 黑体 / 等线 / 宋体，均缺失时回退 Helvetica（中文将显示为方框，需补装字体）。

## 十一、图片检出类别分布指标

统计页只选取每份源图片最新一次成功检测，排除视频，并明确按检测日期筛选。图片详情展示该图的类别分布；视频不计算此看板。指标只描述模型检出类别和框数，不代表物种、独立生物个体数或生态质量。口径与代码见 `app/core/ecology.py`。

### 指标定义

记 S = 检出类别数，N = 检出框数，pᵢ = nᵢ / N 为第 i 类框数占比：

| 指标 | 公式 | 含义 |
| --- | --- | --- |
| Shannon 类别分布 H' | H' = −Σ pᵢ·ln(pᵢ) | 描述检出类别的分布，理论上限为 ln(S) |
| Simpson 分布指数 D | D = 1 − Σ pᵢ² | 描述检出框在类别间的分布 |
| Pielou 均匀度 J' | J' = H' / ln(S) | 在已知有 S 个类别的条件下分布有多均匀，取值 0~1 |
| Margalef 类别丰富度 | d = (S − 1) / ln(N) | 仅反映当前检出类别与框数的关系 |

另给出检出最多的类别与类别丰度表（含累计占比，用于帕累托图）。

### 边界处理（重要）

系统对无意义的取值**返回 `null` 而不是 0**，避免误读：

- **类别数为 0 或个体总数为 0**：全部指数返回 `null`，页面显示「—」；
- **仅 1 个类别**：`J'` 返回 `null`（数学上 ln(1) = 0 导致无定义，只有一类时"均匀度"没有意义），
  而 `H' = D = 0` 是**正确结果**会照常返回；
- **个体总数 = 1**：`Margalef` 返回 `null`（分母 ln(1) = 0）；
- 占比在计算前会**重新归一化**，不依赖上游 `ratio` 字段，避免舍入误差污染指数。

> 中文解读显示当前类别数下的理论上限与均匀度，不再按固定 1/2/3 阈值评判生态质量；缺测日期保持断线。

### 前端一致性

记录详情弹窗里的指标由前端用 `class_stats` **就地计算**（省一次请求），
公式与后端完全一致 —— 已验证同一条记录在两处显示相同数值（示例记录 4092：
H'=0.4293 / D=0.2604 / J'=0.6194 / Margalef=0.3899）。

## 十三、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面提示「未检测到模型权重文件」 | 把 `.pt` 放进 `models/`，或用 `MODEL_PATH` 指定路径，再重启 |
| 视频上传后提示「编码可能不受支持」 | 转成 MP4（H.264）编码后重试，可用格式工厂 / FFmpeg 转换 |
| 启动时提示端口被占用 | 程序会自动切换到下一个可用端口，也可用 `--port` 指定 |
| 检测结果为空 | 降低置信度阈值（图片检测页可直接改），确认权重与训练类别匹配 |
| 检测结果类别名是数字或 class_x | 权重文件未包含类别名，确认导出模型时带上了 names |
| 想清空所有历史数据 | 停止服务后删除 `data/app.db`，重启会自动重建空库 |
| 磁盘里的 MP4 / 图片越积越多 | 调用 `POST /api/system/cleanup`（先加 `?dry_run=true` 预检），详见第九章 |
| 开第二个标签页检测视频被弹窗拒绝 | 跟踪为全局独占资源，并发会导致统计出错，等待首个任务结束后重试即可 |
| 检测报告里的中文显示成方框 | 系统缺少中文字体，安装微软雅黑 / 黑体 / 等线 / 宋体任一即可 |
| 「下载检测报告」按钮是灰的 | 只有至少一张图片检测成功时才可点击；全部失败时无可用数据 |
| 改了前端页面但浏览器看不到变化 | 已对 HTML/JS/CSS 下发 `Cache-Control: no-cache`；若仍异常，强制刷新（Ctrl+F5）清掉旧副本 |
| pip 下载 torch 很慢 | 使用 `--index-url https://download.pytorch.org/whl/cpu`，或换国内 PyPI 镜像装其它包 |

## 十四、扩展说明

- **目标跟踪（已实现）**：视频检测通过 `engine.track()` 调用 ultralytics `model.track(persist=True)`
  （默认 ByteTrack），跨帧保持 track_id，据此统计唯一目标数、轨迹 ID 与出现帧数。
  跟踪使用**独立模型实例**，避免 ultralytics 的 tracker 回调污染图片推理路径；
  缺少 `lap` 依赖时自动回退为逐帧检测，功能不中断。
- **前端绘框**：服务端只推送原始帧 + 检测结果（bbox / 类别 / 置信度 / track_id），检测框由前端
  Canvas 绘制，因此支持「按类别实时筛选」与轨迹 ID 标注；服务端仍保存绘制版结果图，供记录页
  缩略图与历史详情使用。
- **结果视频导出**：视频任务在检测的同时，把带检测框的画面写入 H.264 / yuv420p MP4（使用本机或 `imageio-ffmpeg` 随附编码器，不在运行时下载）。输出帧率按
  跳帧折算（`fps / frame_skip`），因此**成片时长与原视频一致**；任务被取消或异常时自动删除
  半成品文件，不留垃圾。可通过 `save_result_video: false` 关闭以节省 CPU 与磁盘。
- **资源治理（已实现）**：`app/core/cleaner.py` 负责按保留天数清理过期文件并同步删除
  关联记录；`app/core/storage.py` 负责引用计数、回收站与审计日志；`app/utils/file_utils.py`
  负责上传去重；`app/core/video_task.py` 的 `VideoTaskManager` 负责任务 TTL 回收；
  `app/db/database.py` 负责 WAL checkpoint。
- **运维可视化（已实现）**：`app/core/sysinfo.py` 聚合运行时指标，`app/api/system.py` 暴露
  状态与运维接口，`web/system.html` + `web/js/system.js` 提供可视化面板。进程与主机指标
  优先取 `psutil`；未安装时自动降级（对应字段显示「不可用」），不影响页面其它部分。
- **回收站恢复的目录识别**：回收站文件名格式为 `{YYYYMMDD}_{HHMMSS}_{序号}_{原名}`，
  时间戳自身含下划线，因此 `original_name_of()` 按固定宽度逐段剥离（8 位日期 + 6 位时间
  + 序号），而不是简单 `split("_", 2)` —— 后者会把时间戳后半段误当作文件名前缀。
  新条目另在 `.metadata` 保存原目录和实际入站时间，恢复时据此还原；旧条目兼容 `result_` / `video_` 前缀。保留窗口按入站时间计算，未知入站时间的旧文件保守保留，恢复不覆盖已有文件。
- 所有 SQL 均为参数化查询，文件上传做了类型与大小校验、文件名清洗，前端展示做了 HTML 转义。
- 数据库支持**增量迁移**：新增列会在启动时自动补齐（见 `app/db/database.py` 的 `_MIGRATIONS`），
  旧 `data/app.db` 无需删除即可升级。


## 调查地图与检测联动

导航中的“养殖地形图”提供三个虚拟海域，初始没有站点，不代表真实地理位置。海面水纹会持续流动，近岸浪花会向沙滩推进并回退；效果仅用于界面展示，不代表实测海流方向或速度。浏览器启用“减少动态效果”时，水面保留静态画面。
从右侧拖入小建筑，或点击“添加站点”后点选地图位置，填写名称即可建立站点。
建筑可再次拖动，站点可改名、编辑参考水深和备注、停用或重新启用；数据保存在服务器数据库。

图片、批量图片与视频检测必须传入启用站点的 `site_id`，不能再手填站点名称。
地图站点档案提供检测入口、图片/视频记录数、分开列出的图片检出合计和视频单帧峰值之和，以及关联记录链接。
统计计数不代表海域实际生物个体数。改名不会改变固定编号，停用也不删除历史关联。
后台已接受的任务可以在站点停用后完成；新提交将拒绝停用站点。

站点 API：`GET/POST /api/stations`，`GET/PUT /api/stations/{id}`。
编辑时需要当前 `version`，旧版本修改会返回 409，避免多个页面互相覆盖。
记录查询支持 `GET /api/records?site_id=编号`，检测记录页也提供站点筛选。
已有无站点旧记录保留，不会自动伪造地图位置或归入新站点。


调查地图支持删除站点。点击站点档案中的“删除站点”后，必须在弹框中确认；取消不会发送删除请求。
`DELETE /api/stations/{id}?version=当前版本号` 仅删除该站点并解除地图关联，检测记录、类别与目标明细、素材文件和原站点名称保留。
删除操作与关联解除在同一事务中完成；过期版本返回 409，防止误删已被其他页面修改的站点。
已接受的检测任务即使在站点删除后完成，也会保留原站点名称并以无地图关联的记录保存。


## 地图动画与助手操作

- 一号、二号和三号养殖所分别沿各自海岸显示动态水纹与拍岸浪花；切换养殖所时，动画跟随当前地图更新。动画层不拦截站点点击、拖动或地图布点操作。
- 地图渲染仅在页面可见时运行，并限制帧率；浏览器启用“减少动态效果”偏好时停止动画。效果是基于虚拟地形图绘制的视觉模拟，不可用于海洋环境判断。
- 页面右下角的鲸鱼助手可通过鼠标或触摸拖动，点击可打开对话；拖动不会误开面板。位置保存在当前浏览器，切换页面或调整窗口后会恢复，键盘方向键也可移动。助手需要在配置中开启并配置模型服务密钥；默认关闭时不会发起外部 AI 请求。

## 开发检查

在克隆后的项目根目录、已安装项目依赖的环境中运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
node tests\frontend_contracts.cjs
```

前端合同检查需另行安装 Node.js。浏览器交互检查需要启动本地服务并使用 Playwright 与 Edge/Chrome。测试会使用临时目录或测试数据库；运行完整测试前请确认 `config.yaml` 指向测试数据位置，避免连接实际数据库。
